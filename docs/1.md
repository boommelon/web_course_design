## 1. 我先用最简单的话讲清楚这个项目

老师好，我这个项目叫“毕业设计管理系统”，主要是给学校管理毕业设计流程用的。

以前毕业设计流程可能要靠线下表格、QQ 或者微信群通知，比如老师出题、学生选题、提交开题报告、老师审核、答辩评分这些流程都比较分散。我的系统就是把这些流程放到一个 Web 系统里面统一管理。

系统里面有三类用户：

1. 管理员：管理用户、审核课题、管理选题流程、管理模板、公告、归档。
2. 教师：发布课题、审批学生选题、上传资料、审核文档、答疑、答辩评分。
3. 学生：浏览课题、申请选题、下载资料、提交文档、查看成绩。

这个项目不是前后端分离项目，而是传统 Java Web 项目。页面用 JSP 写，后台用 Servlet 接收请求，数据库操作用 JDBC，数据库是 MySQL，运行在 Tomcat 9 上，Maven 负责管理依赖和打包。

## 2. 这个项目目录分别是干嘛的

项目主要目录是这样的：

```text
src/main/java
  bean        实体类，也就是用 Java 类表示数据库里的数据
  controller  Servlet 控制器，接收页面请求，决定调用哪个业务
  dao         数据访问层，专门负责查数据库、改数据库
  dbutil      数据库工具类，主要是 SQLHelper
  filter      过滤器，负责编码和登录权限控制
  util        工具类，比如密码加密、参数转换、文件上传

src/main/webapp
  login.jsp   登录页面
  WEB-INF/jsp 后台 JSP 页面，按管理员、教师、学生分类
  static      CSS 和 JS 静态资源

sql
  init.sql    数据库初始化脚本
```

我答辩时可以这样讲：

> 我的项目是按 Java Web 常见的 MVC 思路分层的。JSP 负责显示页面，Servlet 负责接收请求和控制流程，DAO 负责数据库操作，Bean 负责封装数据，Filter 负责统一的登录和权限控制，SQLHelper 负责统一连接 MySQL。

## 3. 从最基础讲：这些 Java Web 名词到底是什么

### 3.1 JSP 是什么

JSP 可以理解成“能写 Java 代码的 HTML 页面”。

普通 HTML 只能写固定内容，但 JSP 可以显示数据库查出来的数据。

比如管理员用户列表页面：

```text
src/main/webapp/WEB-INF/jsp/admin/users.jsp
```

这个页面会显示用户表格，还能点新增、编辑、删除、重置密码。

我答辩时可以这样说：

> JSP 在我的项目里主要负责页面展示。比如管理员用户管理页面、教师课题管理页面、学生文档提交页面，都是 JSP。Controller 查到数据以后，会放到 request 里面，然后 JSP 用 JSTL 把数据循环显示出来。

### 3.2 Servlet 是什么

Servlet 可以理解成“Java 写的后台入口”。

页面提交表单以后，不是 JSP 自己直接操作数据库，而是请求先进入 Servlet。

比如登录页面提交到：

```text
/login.action
```

这个地址对应的 Java 类是：

```text
src/main/java/controller/LoginController.java
```

`LoginController` 会接收用户名和密码，然后调用 DAO 去数据库验证。

我答辩时可以这样说：

> Servlet 是控制器，负责接收浏览器请求。比如登录、发布课题、提交选题、上传文档这些操作，都是先进入对应的 Controller。Controller 不直接写页面，也不直接拼 SQL，而是负责调度流程。

### 3.3 doGet 和 doPost 是什么

Servlet 里面常见两个方法：

```java
doGet()
doPost()
```

简单理解：

- `doGet`：一般用来打开页面、查询列表、查看数据。
- `doPost`：一般用来提交表单，比如新增、编辑、审核、上传文件。

项目里的例子：

- `AdminUserController.doGet()`：显示用户列表、删除用户、重置密码。
- `AdminUserController.doPost()`：新增用户、编辑用户。
- `StudentDocumentController.doPost()`：学生提交文档。

我答辩时可以这样说：

> 在我的项目里，GET 更多用于页面展示，POST 更多用于表单提交。比如用户管理页面打开时走 doGet，新增用户表单提交时走 doPost。

### 3.4 Bean 实体类是干嘛的

这个一定要讲清楚。

Bean 实体类就是“用 Java 对象表示一条数据库记录”。

比如数据库 `users` 表里面有这些字段：

```text
id
username
password
name
role
email
phone
```

代码里就有一个对应的实体类：

```text
src/main/java/bean/User.java
```

这个 `User` 类里面会有：

```text
id
username
password
name
role
email
phone
```

还有对应的 `get` 和 `set` 方法。

为什么需要实体类？

因为数据库查出来的是一行一行的数据，Java 代码直接操作这些字段会很乱。所以把一行用户数据封装成一个 `User` 对象，后面 Controller、JSP、DAO 都可以传这个对象。

举个口语例子：

> 数据库里的一行用户记录，拿到 Java 里面就变成一个 User 对象。比如登录成功后，我不是只保存用户名，而是把整个 User 对象放到 session 里，这样后面就能知道当前用户的 id、姓名、角色。

项目里的常见实体类：

| 实体类 | 对应业务 | 大概作用 |
| --- | --- | --- |
| `User` | 用户 | 表示管理员、教师、学生 |
| `Topic` | 课题 | 表示教师发布的毕业设计课题 |
| `TopicSelection` | 选题申请 | 表示学生申请哪个课题、状态是什么 |
| `Document` | 文档 | 表示学生提交的开题报告、论文、源代码 |
| `FileItem` | 文件 | 表示模板文件、教师资料 |
| `Evaluation` | 自评互评 | 表示综合评价和分数 |
| `DefenseScore` | 答辩成绩 | 表示学生答辩分数和意见 |
| `Announcement` | 公告 | 表示系统公告 |

老师如果问“实体类有什么用”，我就这样回答：

> 实体类主要是封装数据。数据库里一张表对应 Java 里的一个类，表里一行数据对应 Java 里的一个对象。这样 Controller 和 JSP 不用直接处理零散字段，而是可以传递 User、Topic、Document 这样的对象，代码更清楚。

### 3.5 DAO 是什么

DAO 全称是 Data Access Object，意思是“数据访问对象”。

简单说：DAO 专门负责和数据库打交道。

比如：

```text
UserDao.java       操作 users 表
TopicDao.java      操作 topics 表
DocumentDao.java   操作 documents 表
```

Controller 不直接写 SQL，而是调用 DAO。

例如登录流程：

```text
LoginController -> UserDao.validate() -> SQLHelper.executeQuery() -> MySQL
```

我答辩时可以这样说：

> DAO 层把数据库操作单独封装起来。Controller 只关心我要验证用户、我要新增课题、我要保存文档，具体 SQL 怎么写放在 DAO 里面。这样分层比较清楚，后期维护也方便。

### 3.6 SQLHelper 是什么

`SQLHelper` 是数据库工具类，路径是：

```text
src/main/java/dbutil/SQLHelper.java
```

它主要做几件事：

1. 加载 MySQL 驱动：`com.mysql.cj.jdbc.Driver`
2. 获取数据库连接：`DriverManager.getConnection(...)`
3. 执行查询：`executeQuery`
4. 执行新增、修改、删除：`executeUpdate`
5. 关闭 `ResultSet`、`Statement`、`Connection`

数据库默认连接：

```text
jdbc:mysql://localhost:3306/graduation_design
```

我答辩时可以这样说：

> SQLHelper 是我封装的数据库工具类。DAO 不用每次都重复写加载驱动、获取连接、关闭连接这些代码，只要调用 SQLHelper 的 executeQuery 或 executeUpdate 就可以。

### 3.7 Filter 是什么

Filter 是过滤器，可以理解成“请求进入 Controller 之前的一道门”。

项目里有两个过滤器：

```text
EncodingFilter.java  统一设置 UTF-8 编码
AuthFilter.java      登录验证和权限控制
```

`AuthFilter` 的逻辑是：

1. 登录页、登录请求、静态资源放行。
2. 其他请求先看 session 里有没有 `loginUser`。
3. 没有登录就跳回 `login.jsp`。
4. 登录了再看角色。
5. `/admin/` 只能管理员访问。
6. `/teacher/` 只能教师访问。
7. `/student/` 只能学生访问。

我答辩时可以这样说：

> Filter 在我的项目里主要解决权限问题。因为不能只靠页面隐藏菜单，用户也可能直接输入地址访问。所以我在 AuthFilter 里统一判断登录状态和角色权限，从后端拦截非法访问。

### 3.8 Maven 是什么

Maven 是项目管理工具。

这个项目的 `pom.xml` 里配置了：

- Java 版本：1.8
- Servlet API：3.1.0
- JSP API：2.3.1
- JSTL：1.2
- MySQL 驱动：8.0.33

我答辩时可以这样说：

> Maven 主要负责依赖管理和打包。比如 MySQL 驱动、JSTL 标签库这些依赖都写在 pom.xml 里，不需要手动复制 jar 包。

### 3.9 Tomcat 是什么

Tomcat 是 Web 服务器，也是 Servlet 容器。

普通 Java 程序可以直接运行 `main` 方法，但 Java Web 项目不是这样。这个项目要部署到 Tomcat，Tomcat 负责接收浏览器请求，然后把请求交给对应的 Servlet。

我答辩时可以这样说：

> Tomcat 负责运行我的 Web 项目。浏览器访问系统地址后，请求先到 Tomcat，再根据 web.xml 里的映射找到对应的 Servlet。

## 4. 一次请求在项目里是怎么走的

可以记住这条线：

```text
浏览器页面
  -> JSP 表单提交
  -> Tomcat 接收请求
  -> Filter 检查登录和权限
  -> Servlet Controller 接收参数
  -> DAO 操作数据库
  -> SQLHelper 执行 SQL
  -> MySQL 返回数据
  -> Controller 放数据到 request
  -> JSP 显示结果
```

答辩时可以这样讲：

> 比如管理员打开用户管理页面，浏览器访问 `/admin/users.action`。请求先经过 AuthFilter，确认当前用户是管理员。然后进入 AdminUserController 的 doGet 方法，Controller 调用 UserDao 查询用户列表，UserDao 通过 SQLHelper 查询 users 表，查到的数据封装成 User 对象列表，再放到 request 里，最后转发到 users.jsp 显示。

比如：

## 7. 登录流程怎么讲

涉及文件：

```text
src/main/webapp/login.jsp
src/main/java/controller/LoginController.java
src/main/java/dao/UserDao.java
src/main/java/util/PasswordUtil.java
src/main/java/filter/AuthFilter.java
```

流程：

1. 用户打开 `login.jsp`。
2. 输入用户名和密码。
3. 表单提交到 `/login.action`。
4. `LoginController.doPost()` 获取参数。
5. 调用 `UserDao.validate(username, password)`。
6. `UserDao` 先用 `PasswordUtil.md5()` 加密密码。
7. 再查 `users` 表。
8. 查到用户就把 `User` 放到 session 的 `loginUser`。
9. 跳转到 `/dashboard.action`。
10. 查不到就返回登录页并显示错误。

可以直接背：

> 登录时，页面把用户名和密码提交到 LoginController。Controller 调用 UserDao 验证用户，UserDao 会把明文密码转成 MD5 后和数据库里的密码比对。验证成功以后，系统把 User 对象保存到 session 的 loginUser 中。后面 AuthFilter 就通过这个 session 判断用户是否已经登录。

老师追问：为什么要放 session？

> 因为 HTTP 请求本身是无状态的。用户登录成功后，如果不保存状态，下一次请求系统就不知道他是谁了。所以我把登录用户放到 session，后续访问页面时都可以从 session 里取出当前用户。

## 8. 权限控制怎么讲

涉及文件：

```text
src/main/java/filter/AuthFilter.java
src/main/webapp/WEB-INF/includes/sidebar.jsp
```

权限控制分两层：

第一层：页面菜单控制。  
`sidebar.jsp` 里根据 `sessionScope.loginUser.role` 显示不同菜单。

第二层：后端 Filter 控制。  
`AuthFilter` 根据 URL 前缀判断角色。

规则：

```text
/admin/   只能 admin 访问
/teacher/ 只能 teacher 访问
/student/ 只能 student 访问
/api/     只有 admin 能访问
```

可以直接背：

> 我的权限控制不是只在页面上隐藏菜单，因为隐藏菜单不安全。真正的权限控制是在 AuthFilter 里做的。所有请求进 Controller 之前都会先经过 Filter，Filter 会判断 session 里有没有 loginUser，再判断当前角色能不能访问这个 URL。

老师追问：学生直接输入管理员地址怎么办？

> 会被 AuthFilter 拦截。比如学生访问 `/admin/users.action`，Filter 发现这个路径是 `/admin/` 开头，但当前用户角色不是 admin，就会重定向回首页。

## 9. opttype 是干嘛的

很多 Controller 里都有：

```java
String action = request.getParameter("opttype");
```

`opttype` 就是“操作类型”。

同一个页面可能有多个按钮，比如用户管理页面有：

- 新增
- 编辑
- 删除
- 重置密码

如果每个按钮都单独写一个 Servlet，类会很多。所以项目用 `opttype` 区分操作。

例子：

```text
opttype=add            新增
opttype=edit           编辑
opttype=delete         删除
opttype=resetPassword  重置密码
opttype=approve        通过
opttype=reject         驳回
```

可以直接背：

> opttype 是我在表单或链接里传的一个操作标识。Controller 收到请求后，先读取 opttype，再用 if 判断当前要执行新增、编辑、删除还是审核。这样一个 Controller 可以管理同一个页面下的多个操作。

## 10. 用户管理怎么讲

涉及文件：

```text
src/main/java/controller/AdminUserController.java
src/main/java/dao/UserDao.java
src/main/webapp/WEB-INF/jsp/admin/users.jsp
```

功能：

1. 查询所有用户。
2. 按角色筛选用户。
3. 新增用户。
4. 编辑用户。
5. 删除用户。
6. 重置密码为 `123456`。

流程：

```text
users.jsp
  -> /admin/users.action
  -> AdminUserController
  -> UserDao
  -> users 表
```

新增用户：

1. 页面提交 `opttype=add`。
2. `AdminUserController.doPost()` 判断是 add。
3. 创建 `User` 对象。
4. 调用 `userDao.insert(user)`。
5. `UserDao` 对密码 MD5 加密。
6. 插入 `users` 表。

重置密码：

1. 页面链接传 `opttype=resetPassword&id=用户ID`。
2. Controller 调用 `resetPassword()`。
3. 实际调用 `userDao.updatePassword(id, "123456")`。
4. `UserDao` 会把 `123456` 做 MD5 后保存。

可以直接背：

> 用户管理由 AdminUserController 负责。页面通过 opttype 区分新增、编辑、删除和重置密码。新增用户时会创建 User 实体对象，再交给 UserDao 插入数据库。重置密码时，Controller 里有一个默认密码常量 `123456`，然后调用 UserDao 更新密码。

## 11. 教师发布课题和管理员审核怎么讲

涉及文件：

```text
src/main/java/controller/TeacherTopicController.java
src/main/java/controller/AdminTopicReviewController.java
src/main/java/dao/TopicDao.java
src/main/java/bean/Topic.java
```

教师发布课题流程：

1. 教师进入“课题管理”。
2. 页面提交课题名称、描述、最大人数。
3. 请求进入 `TeacherTopicController.doPost()`。
4. Controller 先检查系统开关 `topic_publish_open`。
5. 创建 `Topic` 对象。
6. 调用 `topicDao.insert(topic)`。
7. 插入数据库时默认：
   - `review_status = pending`
   - `status = closed`

为什么默认关闭？

因为教师刚发布的课题不能让学生马上选，必须先经过管理员审核。

管理员审核流程：

1. 管理员进入“课题审核”。
2. 请求进入 `AdminTopicReviewController`。
3. 如果通过，调用 `topicDao.updateReview(id, "approved", comment)`。
4. `TopicDao` 会把：
   - `review_status` 改成 `approved`
   - `status` 改成 `open`
5. 学生才能在浏览课题页面看到。

可以直接背：

> 教师发布课题后，课题不是马上开放的，而是 pending 待审核状态，并且 status 是 closed。管理员审核通过后，review_status 变成 approved，status 变成 open，学生才能浏览和申请。这样保证了课题发布需要管理员把关。

涉及文件：

## 17. 3 分钟项目介绍稿

老师好，我的毕业设计项目是“毕业设计管理系统”。这个系统主要是为了管理毕业设计从教师出题、管理员审核、学生选题、文档提交、教师审核、答辩评分到最终归档的完整流程。

系统分为管理员、教师和学生三种角色。管理员主要负责用户管理、课题审核、选题管理、模板管理、公告管理、系统开关和后期归档。教师主要负责发布课题、审批学生选题、上传资料、审核学生文档、回答学生问题和录入答辩成绩。学生主要负责浏览课题、申请选题、下载资料、提交开题报告、中期检查、毕业论文、源代码，并查看自己的成绩和反馈。

技术上，我使用的是传统 Java Web 技术。前端页面用 JSP 展示，后端用 Servlet 接收请求，数据库操作放在 DAO 层，通过 JDBC 连接 MySQL。项目通过 Maven 管理依赖，部署在 Tomcat 9 上运行。

整个项目采用分层结构。JSP 负责显示页面，Controller 负责处理请求，DAO 负责操作数据库，Bean 实体类负责封装数据，Filter 负责登录和权限控制，SQLHelper 负责统一连接数据库。

我项目里比较重要的流程是：教师发布课题后，课题默认是待审核状态；管理员审核通过后，学生才能浏览并申请；学生提交申请后，教师或管理员审批；选题通过以后，学生才能提交文档；教师审核文档后，学生可以查看分数和反馈；最后教师录入答辩成绩，管理员进行归档。

这个系统基本覆盖了毕业设计管理的主要流程，也体现了 Java Web 中页面展示、请求处理、数据库 CRUD、权限控制和文件上传下载这些核心知识。

## 18. 5 分钟代码讲解稿

老师好，我代码讲解主要按一次请求的执行流程来讲。

首先是登录功能。登录页面是 `login.jsp`，表单提交到 `/login.action`，对应的 Controller 是 `LoginController`。在 `doPost` 方法里，系统通过 `request.getParameter()` 获取用户名和密码，然后调用 `UserDao.validate()`。DAO 里面先用 `PasswordUtil.md5()` 把密码加密，再通过 `SQLHelper.executeQuery()` 查询 `users` 表。如果查到用户，就把 `User` 实体对象保存到 session 的 `loginUser` 里，然后跳转到首页。

第二是权限控制。项目里有 `AuthFilter`，它相当于所有请求进入 Controller 前的一道门。登录页面、登录请求和静态资源会放行，其他请求都要检查 session 里有没有 `loginUser`。如果没登录就跳回登录页。如果已经登录，再根据 URL 前缀判断角色，比如 `/admin/` 只能管理员访问，`/teacher/` 只能教师访问，`/student/` 只能学生访问。

第三是 Controller 的写法。项目里很多 Controller 都用 `opttype` 区分操作。比如 `AdminUserController` 里，`opttype=add` 表示新增用户，`opttype=edit` 表示编辑用户，`opttype=resetPassword` 表示重置密码。这样一个用户管理 Controller 就可以处理同一个页面上的多个按钮。

第四是实体类和 DAO。实体类在 `bean` 包里，比如 `User`、`Topic`、`Document`。它们主要负责封装数据。DAO 在 `dao` 包里，比如 `UserDao`、`TopicDao`、`DocumentDao`，它们专门负责写 SQL 操作数据库。Controller 不直接操作数据库，而是调用 DAO。DAO 再调用 `SQLHelper` 获取连接、执行 SQL、关闭资源。

第五是课题流程。教师发布课题由 `TeacherTopicController` 处理，新增课题前会检查 `topic_publish_open` 开关。课题保存时默认是 `pending` 待审核和 `closed` 未开放。管理员在 `AdminTopicReviewController` 审核课题，通过后 `review_status` 变成 `approved`，`status` 变成 `open`，学生才能看到并申请。

第六是选题流程。学生提交选题申请由 `StudentSelectionController` 处理，会先检查选题开关和学生是否已经有有效申请。申请保存到 `topic_selections` 表，状态是 `pending`。教师审批由 `TeacherSelectionController` 处理，通过时会检查课题是否属于当前教师、人数是否已满。通过后状态改成 `approved`，课题已选人数加一，满员就关闭课题。

第七是文档上传。学生文档提交由 `StudentDocumentController` 处理，类上用了 `@MultipartConfig` 限制上传大小。上传前会检查学生是否已经选题通过，以及文档上传开关是否开启。文件保存到服务器目录，数据库保存文件路径、文件名、文档类型和摘要。教师审核文档由 `TeacherDocumentController` 处理，会保存分数、反馈和审核状态。

最后是答辩评分和归档。教师通过 `TeacherDefenseController` 给自己指导的学生录入答辩成绩，系统会判断学生和教师的指导关系。管理员通过 `AdminArchiveController` 查看统计数据，并可以关闭整个项目流程。

## 20. 老师可能问的 30 个问题和回答

### 1. 你的项目是做什么的？

答：

> 我的项目是毕业设计管理系统，主要管理毕业设计从教师出题、管理员审核、学生选题、文档提交、教师审核、答辩评分到最终归档的完整流程。

### 2. 你的项目用了哪些技术？

答：

> 使用 Java Web 技术，页面是 JSP，后台是 Servlet，数据库操作用 JDBC，数据库是 MySQL，服务器是 Tomcat 9，项目用 Maven 管理依赖。

### 3. 你的项目分几层？

答：

> 主要分为 JSP 页面层、Servlet 控制层、DAO 数据访问层、Bean 实体层、Filter 权限控制层和 SQLHelper 数据库工具层。

### 4. 实体类是干嘛的？

答：

> 实体类就是用 Java 对象封装数据库数据。比如 users 表的一行数据，在 Java 里就是一个 User 对象。这样 Controller、DAO、JSP 之间传数据更方便。

### 5. DAO 是干嘛的？

答：

> DAO 专门负责操作数据库，比如查询用户、插入课题、更新文档状态。Controller 不直接写 SQL，而是调用 DAO。

### 6. Controller 是干嘛的？

答：

> Controller 就是 Servlet，负责接收请求、获取参数、判断操作类型，然后调用 DAO，最后跳转到对应 JSP 页面。

### 7. JSP 是干嘛的？

答：

> JSP 负责显示页面，比如用户列表、课题列表、文档提交表单。Controller 把数据放到 request 里，JSP 再显示出来。

### 8. Filter 是干嘛的？

答：

> Filter 是过滤器，请求进入 Controller 前会先经过 Filter。我的项目里主要用它做 UTF-8 编码和登录权限控制。

### 9. SQLHelper 是干嘛的？

答：

> SQLHelper 是数据库工具类，统一负责获取数据库连接、执行 SQL、关闭资源，避免每个 DAO 重复写连接代码。

### 10. 登录怎么实现？

答：

> 登录表单提交到 LoginController，Controller 调用 UserDao.validate 查询数据库。验证成功后，把 User 对象保存到 session 的 loginUser 中。

### 11. 密码是明文存的吗？

答：

> 不是。项目里用 PasswordUtil.md5() 把密码转成 MD5 后再保存到数据库。比如重置密码 123456 时，也是保存 123456 的 MD5 值。

### 12. 权限怎么保证？

答：

> 主要靠 AuthFilter。它先判断是否登录，再根据 URL 前缀判断角色。比如 `/admin/` 只能管理员访问，学生直接访问会被拦截。

### 13. 只隐藏菜单可以吗？

答：

> 不可以。隐藏菜单只是前端显示控制，真正安全要靠后端拦截。所以项目里既有 JSP 菜单控制，也有 AuthFilter 后端权限控制。

### 14. opttype 是什么？

答：

> opttype 是操作类型参数。比如 add 表示新增，edit 表示编辑，approve 表示通过，reject 表示驳回。Controller 根据 opttype 决定执行哪个方法。

### 15. doGet 和 doPost 有什么区别？

答：

> 我项目里一般 doGet 用来打开页面和查询列表，doPost 用来提交表单，比如新增、编辑、审核、上传文件。

### 16. 数据库怎么连接？

答：

> 通过 SQLHelper 连接 MySQL。里面配置了 MySQL 驱动、数据库 URL、用户名和密码，然后用 DriverManager.getConnection 获取连接。

### 17. 怎么防止 SQL 注入？

答：

> DAO 里用的是 PreparedStatement，通过问号占位传参数，不是直接拼接用户输入，所以能减少 SQL 注入风险。

### 18. 教师发布课题后，学生能马上选择吗？

答：

> 不能。教师发布后课题默认是 pending 待审核和 closed 关闭状态。管理员审核通过后才变成 approved 和 open。

### 19. 学生可以重复选题吗？

答：

> 不可以。提交选题前会调用 hasActiveSelection 判断学生是否已经有 pending 或 approved 状态的申请。

### 20. 课题人数满了怎么办？

答：

> 教师审批通过后，系统会让 selected_count 加 1，然后调用 closeIfFull 判断是否满员，满员就把课题状态改成 closed。

### 21. 管理员可以干预选题吗？

答：

> 可以。管理员可以审批选题，也可以给未选学生做最终分配，还能设置选题轮次和开关。

### 22. 学生没选题能提交文档吗？

答：

> 不能。StudentDocumentController 上传前会先查学生有没有 approved 状态的选题，没有就不允许提交。

### 23. 文档上传怎么实现？

答：

> Servlet 使用 @MultipartConfig 支持文件上传，通过 request.getPart("file") 获取文件，然后保存到服务器目录，数据库保存文件路径、文件名、类型和摘要。

### 24. 文件直接存数据库吗？

答：

> 没有。数据库只保存文件路径和文件名，真实文件保存在服务器目录。这样数据库压力小，下载时再根据路径读取文件。

### 25. 上传文件有限制吗？

答：

> 有。StudentDocumentController 里设置了单文件最大 20MB，整个请求最大 25MB。

### 26. 下载怎么防止越权？

答：

> 文档下载不是直接访问文件路径，而是通过 DocumentDownloadController。它会判断当前用户角色，学生只能下载自己的，教师只能下载自己课题下的。

### 27. 教师可以审核所有学生文档吗？

答：

> 不可以。DocumentDao.updateReview 里通过 documents 关联 topics，并且要求 topics.teacher_id 等于当前教师 id。

### 28. 答辩评分怎么保证教师只能给自己学生打分？

答：

> TeacherDefenseController 会调用 isStudentOfTeacher 判断这个学生是否是当前教师指导的已通过选题学生，不是的话不能保存评分。

### 29. 系统开关有什么用？

答：

> 系统开关用来控制流程阶段，比如是否允许教师出题、是否允许学生选题、是否允许上传文档。这样管理员可以按毕业设计进度控制系统。

### 30. 项目有什么不足？

答：

> 项目功能流程基本完整，但也有可以改进的地方。比如密码加密可以从 MD5 升级为 BCrypt，文件上传可以增加文件类型白名单，删除操作可以增加日志记录。

## 22. 高频追问：项目难点是什么

可以直接回答：

> 我觉得难点主要是流程状态和权限控制。因为毕业设计不是一个简单 CRUD，它有很多状态，比如课题有 pending、approved、rejected，选题也有 pending、approved、rejected，文档有 submitted、reviewed、rejected。不同状态下，不同角色能做的事情不一样。所以我通过状态字段、系统开关、Filter 权限控制和 DAO 条件一起保证流程正确。

再补一句：

> 比如学生没选题通过不能提交文档，教师不能审核别的教师学生的文档，学生不能访问管理员页面，这些都是项目里重点处理的地方。

## 23. 高频追问：怎么保证权限安全

可以直接回答：

> 第一层是登录控制，AuthFilter 判断 session 中有没有 loginUser，没有就跳回登录页。第二层是角色控制，Filter 根据 URL 前缀判断 admin、teacher、student。第三层是数据库操作控制，比如教师修改课题和审核文档时 SQL 条件里会带 teacher_id，防止教师操作别人的数据。第四层是下载控制，下载文件时会再次判断当前用户和文件的关系。

## 24. 高频追问：怎么连接数据库

可以直接回答：

> 数据库连接统一放在 SQLHelper 里。SQLHelper 先加载 MySQL 驱动，然后通过 DriverManager.getConnection 获取连接。DAO 层调用 SQLHelper.executeQuery 做查询，调用 executeUpdate 做新增、修改和删除。这样数据库连接代码集中管理，不用每个 DAO 重复写。

---

## 25. 高频追问：上传文件怎么实现

可以直接回答：

> 上传文件主要在 StudentDocumentController 里实现。Servlet 上加了 @MultipartConfig，表示支持 multipart 文件上传。提交时通过 request.getPart("file") 获取文件，然后生成一个带时间戳和用户 ID 的安全文件名，保存到服务器 uploads 目录。数据库 documents 表里保存文件路径、原文件名、文档类型、摘要、学生 ID 和课题 ID。

如果老师问“为什么数据库不直接存文件？”

> 因为文件可能比较大，直接存数据库会增加数据库压力。一般做法是文件存在服务器或文件存储中，数据库只保存路径和业务信息。

老师好，我这个项目是毕业设计管理系统，用 Java Web 实现，技术上是 JSP、Servlet、JDBC、MySQL、Tomcat 和 Maven。系统有管理员、教师、学生三种角色。管理员负责用户、课题审核、选题管理和归档；教师负责发布课题、审批选题、审核文档和答辩评分；学生负责选题、提交文档和查看成绩。
